# 账本模板设计

## 核心原则

1. **Template 是 Blueprint，不是 Book** — 模板是账本的创建蓝图，不是账本的父对象
2. **Template 是 Snapshot，不是 Reference** — 创建时复制一次，之后完全脱离
3. **Template 描述结构，不描述历史数据** — 不含交易记录、余额等运行时数据
4. **Account 是 User 的资源，永远不进入 Template** — 账户全局共享，模板只生成账本级结构

## 数据模型

### book_template 表

| 字段 | 说明 |
|---|---|
| id | 主键 |
| name | 模板名称 |
| icon | 图标 |
| description | 描述 |
| type | SYSTEM / USER |
| creator_id | SYSTEM 为 null，USER 为用户 id |
| version | 内容版本（同一模板的迭代号） |
| schema_version | JSON 结构版本（用于 configJson 格式迁移） |
| config_json | 完整配置快照 |
| created_at / updated_at | 时间戳 |

唯一约束：`UNIQUE(creator_id, name)`（USER 类型下同名限制，按产品需求定）

### configJson 结构

```json
{
  "bookSettings": { "currency": "CNY", "notes": "..." },
  "categories": {
    "expense": [{ "name": "餐饮", "children": [...] }],
    "income": [{ "name": "工资" }]
  },
  "tags": [{ "name": "固定支出" }],
  "payees": [{ "name": "支付宝" }]
}
```

TemplateCategory / TemplateTag / TemplatePayee 是普通 DTO/record，不是 JPA Entity。

## 模板类型

| 类型 | 来源 | 存储 | 说明 |
|---|---|---|---|
| SYSTEM | 官方内置 | `resources/templates/*.json`，启动时加载到内存 | 开源部署者可直接修改 JSON 文件 |
| USER | 用户保存当前账本 | 数据库 | 仅创建者可见 |

系统模板通过 `SystemTemplateProvider` 启动时解析 JSON 并缓存，不走数据库。

## 模板包含什么

### 必含（核心价值）
- 支出分类树 + 收入分类树（最深 4 级）
- 标签列表

### 可选
- 交易对象（系统模板只放通用对象如支付宝、微信；用户模板默认不导出 Payee，由用户勾选）
- 账本配置（币种建议、备注模板）

### 永远不含
- Account（账户是用户级资源）
- Transaction / MoneyFlow（历史数据）
- 余额
- 预算、规则等高级功能（MVP 不做，后续扩展）

## 关键领域组件

```
BookService.createBook()           ← 事务边界在这里
  ├── 创建 Book
  └── TemplateApplier.apply(book, config)
        ├── CategoryImporter
        ├── TagImporter
        └── PayeeImporter

Book → TemplateExporter → BookTemplate   （保存为模板）

configJson → TemplateConfigParser → TemplateConfig → TemplateValidator → TemplateApplier
```

- **TemplateApplier**：将 TemplateConfig 应用到新账本，单一职责
- **TemplateExporter**：从现有账本导出为模板配置，负责脱敏/筛选
- **TemplateValidator**：校验 config 合法性（数量限制、结构合法性）
- **TemplateConfigParser**：JSON → TemplateConfig，JSON 只是存储格式不是业务模型
- **TemplateConfigMigrator**：跨 schemaVersion 的格式迁移

事务边界在 `BookService.createBook()`（完整用例），不在 TemplateApplier。

## API 设计

### 创建账本（扩展现有接口）

```
POST /api/books
{
  "name": "我的账本",
  "currencyId": 1,
  "notes": "",
  "templateId": 1001   // null = 空白账本
}
```

### 模板接口

```
GET    /api/book-templates          // 列表：系统 + 我的
GET    /api/book-templates/{id}     // 详情
POST   /api/book-templates          // 保存当前账本为模板
DELETE /api/book-templates/{id}     // 删除个人模板
```

### 保存为模板的请求体

```json
{
  "name": "我的家庭账本",
  "includeCategories": true,
  "includeTags": true,
  "includePayees": false,
  "includeSettings": true
}
```

默认不勾选 Payee，降低隐私风险。

## Book 实体变更

**不增加** templateId 外键（不建立运行时关联）。如需溯源，可加：

```
source_template_key      // 模板 key，null 表示非模板创建
source_template_version  // 创建时的模板版本
```

仅作审计/展示用，不参与任何业务逻辑。

## 规模限制

避免恶意/错误数据：
- Category ≤ 1000
- Tag ≤ 1000
- Payee ≤ 1000

## MVP 明确不做

- Template → Book 持续关联 / 自动升级
- 已有账本应用模板（覆盖或合并）
- 模板包含 Account / Transaction / 余额
- TemplateCategory / Tag / Payee 的 JPA 实体（用 JSON）
- 社区模板 / 模板市场 / 评分 / 订阅
- 预算、规则等高级配置

## 未来扩展方向

- 社区模板 → 增加模板索引表（template_category_index 等），不改主模型
- 已有账本应用模板 → 只支持**合并**（新增不存在的，保留已有），绝不覆盖
- 部署者自定义系统模板 → 支持 `config/templates/` 覆盖 `resources/templates/`
- 模板搜索 → 增加独立索引表，主表继续存 JSON
