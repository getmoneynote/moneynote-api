# 前端经验

## 退出登录：先作废后端会话，整页跳转清内存态

`UserMenu.jsx` 的 logout 约定：

- **调用顺序**：`await userApi.logout()` → `clearAccessToken()` → `window.location.href = '/login'`。退出接口 `skipErrorHandler: true` 且 try/catch 吞掉异常——断网或会话已失效时不能卡住本地退出，本地清理不依赖接口结果。
- **跳转用整页 `window.location.href`，不用 `history.replace`**：与 `errorHandler.js` 的 401 处理（`handle401`）保持一致。SPA 内部跳转不会重置 `initialState.currentUser`、useRequest 缓存等内存态，退出后按浏览器「后退」会短暂回到原页面并发出带不上 token 的请求（401 弹错误 toast）；整页跳转顺带把内存态清零。
- **退出前 `App.useApp()` 的 `modal.confirm` 二次确认**：拦截器模块拿不到 context 才走 AppBridge，组件内直接 `useApp()` 即可。

## 弹窗内「不提交的二次操作」（如测试连接）

表单弹窗里需要「拿当前表单值做一件非提交的事」（llmConfig 的测试连接）时：

- 给 `BaseModalForm` 传 `formRef`（`useRef()`，壳层会透传给 ModalForm），按钮 onClick 里 `await formRef.current.validateFields()` 拿校验后的值再调接口——校验失败会 reject 并显示红字，天然拦截。
- 按钮 loading 态自己管（`useState`），失败提示交给 request errorHandler，`finally` 里复位 loading。
- 样板：`src/pages/llmConfig/ActionForm.jsx`。

## 敏感字段编辑约定：留空 = 不修改

apiKey 这类敏感字段后端列表只回传掩码（`****` + 后 4 位），编辑弹窗**不回填**。前后端配套约定：

- 后端 UpdateForm 所有字段可空，`StringUtils.hasText` 判断「传了才改」；
- 前端编辑时该字段 `required: !isEdit`，placeholder 提示「留空表示不修改」，提交时原样带上（空串/undefined 后端自动忽略）；
- 「测试」类接口支持 apiKey 留空 + 带 id，由后端取库存 key（用户不改 key 也能测）。
